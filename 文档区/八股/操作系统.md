# 操作系统

## JS的单线程模型与操作系统的多线程如何协作？

js主进程只有一个，但是浏览器会使用多个系统线程来完成异步任务，最后通过事件循环返回结果

### JS为什么是单线程语言

1. 开发模型更简单： javascript一开始被设计来是用于网页交互的，而网页交互的大部分需求都是基于用户事件，这些都**需要较快的响应速度**，如果设计成多线程，那可能就要处理其他任务，导致页面卡顿，因此要**避免多线程编程所带来的复杂性**。但是现在也通过了异步编程，事件循环机制等手段来实现高效的并发处理。
2. 避免多线程同时修改DOM导致状态一致性问题。

### 浏览器如何用多线程协作

- setTimeout 执行在定时器线程
- 网络请求 执行在 NetworkThread，
- 文件读取 OS的 File I/O线程
- Layout/Raster 合成线程
- Web worker 独立的系统线程

### 事件循环的意义

EventLoop 只是调度中心，不执行异步操作本体。  
异步操作本体由浏览器线程或 OS 线程完成。

这是前端理解性能和异步的基础。

## 浏览器为何禁止 JS 直接访问文件系统？

### 如果 JS 可以读本地文件，会发生什么？

任何网站都可以：

- 读取你的 SSH 密钥
- 读取你的微信/浏览器密码数据库
- 读取公司源代码、文档
- 写入木马  

### 浏览器的安全沙箱

浏览器对页面 JS 设置了非常强的限制：

- 页面 JS 无法调用系统 API
- 无法访问真实的文件路径
- 无法访问其他应用的进程、内存
- 无法进行任意网络访问（必须遵守 CORS）

### 允许的方式必须获得用户授权

如：

- <input type="file">（需要用户选择）
- File System Access API（必须弹窗授权）
- sandboxed OPFS（隔离的虚拟文件系统）

核心理念是：网页是不可信的代码，绝不能给它操作系统权限。

## 进程与线程的区别 + 前端场景对应（必会

### 进程线程 概念区分

进程Process：
  拥有独立的内存空间，通信时使用IPC，通信成本高，但是一个崩溃不会影响其他的进程

线程Thread：
  共享进程内存，通信成本低，但是一个崩溃可能会拖垮整个进程

### 浏览器中的体现

- 浏览器中的每一个tab都对应一个渲染进程Process，所以一个死掉不影响其他的
- JS主线程，渲染进程中的OSthread

### 为什么浏览器使用多进程

- 单个页面崩溃不会影响其他页面
- 提升安全性（沙箱）
- 利用多核 CPU

### 为什么 JS 本身不允许多线程访问 DOM？

避免出现：

- 写时竞争（race condition）
- 锁问题（mutex、deadlock）
- 内存一致性模型复杂化

## 页面卡顿的主要原因

页面卡顿是由于： “主线程被阻塞”

### JS执行时间长

- 大量数据处理
- 复杂循环
- JSON 超大对象解析
- 加密算法、图像处理

### 频繁DOM修改，导致回流重绘

重新绘制DOM树，计算布局、合成都耗时

### 内存泄漏

由内存泄漏导致了：

- 浏览器内存占用持续上升
- OS触发Swap/page fault -> 卡顿非常明显

### 阻塞I/O

- localStorage 是同步 API
- 同步 XHR 造成主线程 freeze

### 渲染层压力过大

- 大量动画
- Canvas连续高频重绘
- 纹理过大导致GPU内存爆掉

## 死锁的面试题

### 死锁含义

多个线程 / 任务，彼此等待资源才能继续下去，最终所有人都无法继续

经典条件（同时满足才会死锁）：

1. **互斥**（资源只能一个线程使用）
2. **占有并等待**
3. **不可抢占**
4. **循环等待**

****

### 前端出现死锁的场景

#### WebWorker 间消息循环导致互相等待

Worker A 等 B 回消息  
Worker B 又等 A 回消息  
双方都卡死

#### Promise 死锁（任务永远不 resolve）

```js
await new Promise(() => {}) 永远无法resolve
```

会导致后续async 逻辑全部被卡住
EventLoop空转

#### 同步 XHR + 主线程资源竞争

主线程执行同步 XHR  
XHR 需要主线程处理事件  
双方等待 → 页面完全假死

### 如何避免死锁

1. 尽量避免共享可写状态
2. 使用不可变数据结构
3. 避免长时间持有资源
4. Worker 间通信要有超时机制
5. 避免使用同步 XHR
6. 避免写永不 resolve 的 Promise
